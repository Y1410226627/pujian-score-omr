# 谱见 · 乐谱识别与试听

一个本地乐谱工作台：查看 PDF/图片乐谱，调用本机 OMR 引擎识谱或导入 MusicXML/MXL，逐音校对后试听、循环演奏任意片段并导出 MIDI。

> **定位说明（重要）**：谱见是「识别结果的**校对与试听**工作台」，不是「上传即出正确旋律」的自动识谱器。
> 图片识别由本机引擎完成，结果**必须逐音校对**。界面会明确标出识别来源（专业引擎 / 粗略估算 / 文件导入），
> 并标出置信度偏低、建议校对的音符。

## 运行

Windows 用户双击 [启动谱见.bat](启动谱见.bat) 即可启动。它会挑选空闲端口、打开浏览器，并在命令窗口运行本地服务；关闭该窗口会停止服务。启动器需要 Python 3.7 或更新版本。也可以在项目目录运行 `py -3 serve.py`，或 `python serve.py`。设置环境变量 `PUJIAN_NO_BROWSER=1` 可在启动时不自动打开浏览器。

需要图片自动识谱时，安装本机引擎（只需一次）：

- **[Audiveris](https://github.com/Audiveris/audiveris)（推荐，整页识别）**：双击 [安装audiveris.bat](安装audiveris.bat)，会把自带 JRE 的 Audiveris 5.11 解包到项目 `.tools/audiveris`（免安装、不写注册表）。装好后整页一次识别即可得到完整的多声部结构，一页约 10–20 秒。
- **[homr](https://github.com/liebharc/homr)（逐谱表识别）**：双击 [安装homr.bat](安装homr.bat)，引擎装入项目 `.venv`；应用会按谱表逐行识别再拼回多声部，单行约 7 秒。

两个引擎都装好后优先用 Audiveris（结构更可靠），失败时自动回退逐行识别，都没有时回退浏览器内粗略估算，界面始终标明识别来源。也可设置 `AUDIVERIS_EXECUTABLE` / `HOMR_EXECUTABLE` 指向自定义路径。

乐谱文件只在本机处理。MusicXML、MXL、试听和 MIDI 导出在浏览器中完成；图片识谱通过本地服务调用本机引擎。项目不会自动安装引擎。PDF 预览组件从 jsDelivr 按需载入，因此打开 PDF 需要网络连接。

## 当前支持

- PDF 翻页和 PNG、JPG、WebP、BMP、GIF 图片预览。
- MusicXML（`.musicxml`、`.xml`）和压缩 MXL（`.mxl`）导入；支持常见的 partwise 结构。
- 从 MusicXML 读取各声部/声部号、音高、升降号、起拍、时值、小节、休止造成的间隔、连音线延音、初始速度、拍号和调号。
- 同一拍的和弦/多声部音符可同时播放；附点、三连音及 MusicXML 中以 `<duration>` 表示的其他时值会按起拍和时长播放。
- 多声部/多谱表按**全局小节长度表**对齐，弱起小节与悬空连音线都能正确处理（见 [tests/musicxml.test.mjs](tests/musicxml.test.mjs)）。
- **Audiveris 整页识别**：一次调用得到完整的多声部结构——各声部在时间轴上并行，弱起小节、拍号、调号、力度、奏法标记都会被保留。对合唱总谱、钢琴谱这类多谱表乐谱，这是目前最可靠的一条路。
- **逐谱表识别（homr）**：把整页按谱线切分成一行行谱表，逐行单独送去识别，再按「系统内并行、系统间顺序」拼回多声部。作为 Audiveris 不可用或失败时的回退。识别过程有进度条与「取消识别」，并支持「只识别第 N 行谱表」重试某一行。
- **识别来源徽标**：明确区分「本机专业识别引擎」「专业引擎 + 部分粗略估算」「粗略估算」「来自文件的结构化乐谱」四种结果。
- **逐音置信度**：粗略估算得到的音符会带上置信分，偏低的音符在列表中以色条标出，可一键「只看待校对」。
- **谱面导航**：识别后在谱面上框出每行谱表的识别区域；点音符行会高亮所属谱表，并在该谱表上画出一条虚线标出这个音的音高位置。
- **演奏任意一段**：点音符序号（或行内空白处）设选区起点、`Shift`+点设终点，即可只试听/导出这一段，并支持循环播放；片段会自动平移到从第 0 拍开始。
- **整体移调**：±12 半音一键校正系统性音高偏差，已手动校对过的音符不会被覆盖。
- **标题可直接编辑**：识别引擎常把谱面编号当成标题，点击标题即可改掉。
- 可点谱面标记定位音符，校对音高、起拍和时值，增删音符；可选择声部/谱表单独试听与导出 MIDI。
- homr 未安装时，五线谱图片可用本地规则逐行估算；可选择高音、低音、中音或次中音谱号。
- 可选调用本机 [homr](https://github.com/liebharc/homr) 识谱；把 `homr` 命令放入 PATH，或在启动前设置 `HOMR_EXECUTABLE` 为可执行文件完整路径。homr 输出会在临时目录处理后删除。本机识谱代码/模型不随本项目捆绑，homr 使用 AGPL-3.0，需按上游说明单独安装并遵守其许可证。

## 当前限制

- **识别精度尚未建立可信基准**：现有验收素材只有一个自造的极简合成谱例，不足以代表真实印刷/扫描谱的精度。评估识别效果前，请先按 `tests/fixtures/known_treble_quarters.ground-truth.json` 的格式补充带人工标注的样本。
- **只支持五线谱**：Audiveris 与 homr 都只识别五线谱。遇到**简谱（数字谱）**页面，应用会明确提示「这页可能是简谱——识谱引擎只支持五线谱」，而不是给出一堆错误音符。
- Audiveris 需要较高分辨率才能可靠检测谱线（实测约 scale ≥ 3.0）；PDF 会按此标准渲染后再送识别。图片本身分辨率过低时会提示换更清晰的图。
- Audiveris 对个别音符仍可能漏读（实测《敕勒歌》第 1 页钢琴声部漏读一个 E4），结果**必须逐音校对**。
- 未安装引擎时，图片/PDF 扫描页只用像素规则粗略估算音高及时值，不会可靠识别调号、休止符、附点、连音、歌词、奏法或复杂复调。
- 引擎可识别的范围和精度由其模型与输入质量决定；力度、奏法、重升降号等不完整，不能保证任意符号。
- 引擎输出的音符**不含谱面坐标**，因此不会在谱面上画音符圆点。界面改为框出每行谱表的识别区域，并在点选音符时画出该音高对应的基准虚线（纵坐标由音高精确推算，横坐标不做猜测）。
- 整页识别（Audiveris）一页约 10–20 秒；逐行识别（homr）单行约 7 秒、一页 12 行约 90 秒（本机 CPU 推理）。16 页的乐谱需要逐页识别。
- 整行休止（或该声部尚未进入）的谱表会被识别为「没有音符」，这是正常结果，界面会单独统计。
- MusicXML 导入用于演奏结构化音符，并不自动识别原始图片；目前只支持 partwise，不支持 timewise 排列。
- 当前试听使用一个合成音色和统一 BPM。只取开头速度；中途速度变化、力度、装饰音、歌词与反复跳转不会体现在演奏中，界面会提示部分限制。
- MusicXML 的微分音可在浏览器合成试听中播放；标准 MIDI 使用整数半音，导出时会四舍五入到最近半音。
- PDF 预览依赖 jsDelivr 上的 pdf.js，离线时无法打开 PDF（可先把页面另存为图片）。
- 本项目不捆绑 OMR 引擎；`.tools/` 与 `.venv/` 均已在 `.gitignore` 中排除，需按上述步骤自行安装。

## 测试

```bash
npm test          # 或 node --test "tests/**/*.test.mjs"
```

- `tests/musicxml.test.mjs`：MusicXML 解析（和弦/休止/连音线/速度/调性/微分音）、悬空连音线、弱起小节、
  多声部小节对齐、全休止乐谱、空标记元素假警告，以及验收素材 ground truth 的自洽性。
- `tests/staff.test.mjs`：谱线分组、系统分组、谱表裁剪框、音高↔坐标换算、整体移调、
  多系统结果合并（系统内并行 / 系统间顺序 / 空谱表处理）。测试数据取自真实谱例《敕勒歌》第 1 页检测到的 60 条谱线。

`tests/generate_omr_fixture.py` 可重新生成验收素材与基准真值（音高由谱面坐标反推，避免图文漂移）。

## 安全说明

本地服务只服务项目根目录下的白名单静态文件（`.html/.css/.js/.mjs/.json/.md/.svg/.ico/.png`），
拒绝 `.venv`、`node_modules`、`.git`、`tests` 等目录与目录列表，校验 `Host` 头，并附带 CSP 等安全响应头。
`/api/omr/recognize` 只接受 PNG/JPEG、限制 25 MB，且同一时刻只处理一个识谱任务。

你提供的完整符号清单与逐项支持状态见 [符号支持清单.md](符号支持清单.md)。公开项目比较见 [GitHub参考项目调研.md](GitHub参考项目调研.md)。
