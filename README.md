# 谱见 · 乐谱识别与试听

一个本地乐谱工作台：查看 PDF/图片乐谱，调用本机 OMR 引擎识谱或导入 MusicXML/MXL，逐音校对后试听、循环演奏任意片段并导出 MIDI。

> **定位说明（重要）**：谱见是「识别结果的**校对与试听**工作台」，不是「上传即出正确旋律」的自动识谱器。
> 图片识别由本机引擎完成，结果**必须逐音校对**。界面会明确标出识别来源（专业引擎 / 粗略估算 / 文件导入），
> 并标出置信度偏低、建议校对的音符。

## 创作室：不会认五线谱也能写谱（新）

打开 **[composer.html](composer.html)**（首页顶栏「✎ 创作室」也能进）。它是给**零乐理基础**的人用的五线谱创作台：

- **选音高**：屏幕上是一台钢琴键盘（C3–C6），点一个键就选定那个音，会立刻响一声；也可以用 ↑/↓ 键一格一格挪。
- **选拍数**：不写「二分音符」「附点四分」，而是「1 拍」「半拍」「2 拍」「1 拍半」这种话。
- **休止符也能放**：想要「空一拍」就选第二排的「休 1」——它占拍数但不出声，谱面上画成休止记号。
- **加进去**：点「＋ 加进乐谱」，五线谱会自己画出来；这个小节还剩几拍，界面上一直写着。
- **多乐器多声部**：可以加任意多个声部，每个声部单独选音色（含二胡、古筝、长笛、合唱等采样音色）与谱号，一起演奏。
- **随时试听**：整首 / 从选中的音开始 / 只听选中的一段（点一个音选中，Shift+点另一个音选一段），支持循环。
- **改错很方便**：撤销/重做、点音符选中后升降半音、加长缩短、删除。
- **导出四种东西**：MusicXML（MuseScore、Finale 等都能打开/打印）、MIDI（任何音乐软件都能放）、MP3 音频（手机/微信/音箱直接放）、
  工程文件（下次导入继续改），以及直接打印浏览器里的五线谱。
- 快捷键：`↑`/`↓` 换音高、`Enter` 加音、`Delete` 删音、`Ctrl+Z` 撤销、`空格` 试听、`Esc` 停止。

导出的 MusicXML 会把每个小节补齐成完整拍数（空出来的地方写休止），所以用别的软件打开不会报「小节不完整」。
五线谱渲染用的是随项目分发的 [VexFlow](https://github.com/0xfe/vexflow)（MIT），完全本地运行，不需要联网。

## 运行

Windows 用户双击 [启动谱见.bat](启动谱见.bat) 即可启动。它会挑选空闲端口、打开浏览器，并在命令窗口运行本地服务；关闭该窗口会停止服务。启动器需要 Python 3.7 或更新版本。也可以在项目目录运行 `py -3 serve.py`，或 `python serve.py`。设置环境变量 `PUJIAN_NO_BROWSER=1` 可在启动时不自动打开浏览器。

默认是「自动挑一个空闲端口」。需要固定端口时（例如写自动化脚本）用 `python serve.py --port 4492`，或设置环境变量 `PUJIAN_PORT=4492`。识谱默认开 2 个 Audiveris 进程并行跑整本，可用 `PUJIAN_OMR_WORKERS=1`（最省内存）到 `4`（最快）调整。

### 第一次运行被 Windows 拦下怎么办

从网上下载的压缩包（浏览器/微信/QQ 保存的 ZIP）会让里面的文件带上**「来自网络」标记**，
双击 `启动谱见.bat` 时 Windows 会弹出：

> 打开文件 - 安全警告　无法验证发布者。你确定要运行此软件吗？

这不是病毒，而是 Windows 对「下载来的、没有数字签名的脚本」的默认提醒。三种处理方式（任选其一）：

1. **直接点「运行(R)」**（只影响这一次）。
2. **永久解除**：右键 `启动谱见.bat` → 属性 → 最下面勾选「**解除锁定**」→ 应用 → 确定。
   如果整个文件夹都是下载来的，可以在 PowerShell 里执行一次：
   `Get-ChildItem -LiteralPath "E:\识谱弹琴" -Recurse -File | Unblock-File`
3. 项目自带的启动器已经内置了自动解除：**成功运行过一次之后**，它会顺手把本项目根目录文件的该标记清掉，之后双击不会再弹。

判断是否还有标记：`Get-Item "E:\识谱弹琴\启动谱见.bat" -Stream *`（只有 `:$DATA` 就是没有标记了）。

**真实音色（采样音源，可选）**：想要「像真钢琴/真合唱/真弦乐/真二胡」的声音，双击 **[安装真实音源.bat](安装真实音源.bat)**
（或 `py -3 tools/install_soundfonts.py`）。它会从官方源下载免费样本到项目内 `.assets/soundfonts/`
（不进 git）：全部安装约 130 MB（67 种音源、5618 个采样条目），也可以只装某一类，例如
`py -3 tools/install_soundfonts.py --only voice`（女声/男声/混声合唱）、`--only strings winds keys`。
装好后音色下拉里会多出 **67 种真实采样音色**（含二胡、古筝、琵琶、笛子、箫、笙、唢呐、扬琴 8 种中国民乐）：真实钢琴、弦乐细分（小提琴/中提琴/大提琴/低音提琴/拨弦/震音/竖琴）、**真实女声合唱 / 男声合唱 / 混声合唱**、11 种管乐、3 种铜管、4 种萨克斯、5 种弹拨/吉他、3 种贝斯、7 种打击、6 种其他民族乐器（完整清单见 [乐器音源清单](docs-instruments.md)）。
来源与许可见 [音源接入方案.md](音源接入方案.md)（Salamander Grand Piano V3、SSO 合唱、
FluidR3_GM，需按各自许可署名；SSO 的样本被转成 24 kHz 单声道，已注明改动）；
没装也完全不影响使用——选到真实音色但没安装时，自动退回同类合成音色。

需要图片自动识谱时，安装本机引擎（只需一次）：

- **[Audiveris](https://github.com/Audiveris/audiveris)（推荐，整页识别）**：双击 [安装audiveris.bat](安装audiveris.bat)，会把自带 JRE 的 Audiveris 5.11 解包到项目 `.tools/audiveris`（免安装、不写注册表），并下载英文 OCR 语言包（约 22 MB）。**没有 OCR 语言包，谱面上的「♩ = 66」速度标记和歌词都读不出来，自动 BPM 会退回默认 84**（可重跑安装器补装）。装好后整页一次识别即可得到完整的多声部结构，一页约 10–20 秒。
- **[homr](https://github.com/liebharc/homr)（逐谱表识别）**：双击 [安装homr.bat](安装homr.bat)，引擎装入项目 `.venv`；应用会按谱表逐行识别再拼回多声部，单行约 7 秒。

两个引擎都装好后优先用 Audiveris（结构更可靠），失败时自动回退逐行识别，都没有时回退浏览器内粗略估算，界面始终标明识别来源。也可设置 `AUDIVERIS_EXECUTABLE` / `HOMR_EXECUTABLE` 指向自定义路径。

乐谱文件只在本机处理。MusicXML、MXL、试听和 MIDI 导出在浏览器中完成；图片识谱通过本地服务调用本机引擎。项目不会自动安装引擎。PDF 预览组件已随项目本地分发（`vendor/pdfjs`），离线也能打开 PDF。

## 当前支持

- PDF 翻页和 PNG、JPG、WebP、BMP、GIF 图片预览。
- MusicXML（`.musicxml`、`.xml`）和压缩 MXL（`.mxl`）导入；支持常见的 partwise 结构。
- 从 MusicXML 读取各声部/声部号、音高、升降号、起拍、时值、小节、休止造成的间隔、连音线延音、初始速度、拍号和调号。
- 同一拍的和弦/多声部音符可同时播放；附点、三连音及 MusicXML 中以 `<duration>` 表示的其他时值会按起拍和时长播放。
- 多声部/多谱表按**全局小节长度表**对齐，弱起小节与悬空连音线都能正确处理（见 [tests/musicxml.test.mjs](tests/musicxml.test.mjs)）。
- **Audiveris 整页识别**：一次调用得到完整的多声部结构——各声部在时间轴上并行，弱起小节、拍号、调号、力度、奏法标记都会被保留。对合唱总谱、钢琴谱这类多谱表乐谱，这是目前最可靠的一条路。
  送引擎的不是屏幕上的显示图，而是**单独重新渲染的识谱图**（普通 PDF 长边 2600px、PNG 无损；图片型低清 PDF 自动放大到 5.0×，第 2 页起再做轻度锐化——实测《有我》p2 的「4 拍小节」占比从 43% 提到 86%、p5 从 25% 提到 96%；第 1 页不锐化是为了让 OCR 读得出速度标记）。
  整本识别时还会把第 1 页读到的**拍号继承给后面不印拍号的页**——否则引擎会把小节时值按谱面宽度猜（实测猜成 5–11 拍），页与页的起拍越飘越远。
- **逐谱表识别（homr）**：把整页按谱线切分成一行行谱表，逐行单独送去识别，再按「系统内并行、系统间顺序」拼回多声部。作为 Audiveris 不可用或失败时的回退。识别过程有进度条与「取消识别」，并支持「只识别第 N 行谱表」重试某一行。
- **整本批量识别（多页 PDF）**：多页 PDF 会多出一个「识别全部 N 页」按钮，一次操作即可逐页渲染、**一次批量送识别**，再用 `mergePageScores` 跨页拼成一份连续的多声部乐谱——小节序号连续、各声部起拍单调递增；拍号/调号只取第一页，单页失败不会中断整批，哪几页失败会如实标出。速度：整本一次送识别省掉了每页的 JVM 启动开销，实测 16 页约 40 秒（**2.5 秒/页**，逐页调用是 9.2 秒/页）；页数多时服务端会按 CPU 自动把页面拆给多个进程并行识别（默认 ≥12 核开 3 个，实测 10 页 3.81 → 2.28–2.50 秒/页）。
  混合谱（例如《敕勒歌》前 10 页五线谱 + 后 6 页简谱）以前只要有一页没有五线谱就整体退回逐页流程（16×9 秒 ≈ 2.4 分钟）；
  现在只把**有谱表的页**批量送去识别，没有谱表的页如实跳过并提示用简谱功能——同一本 16 页混合谱实测 **24.6–26.4 秒**。
- **简谱（数字谱）识别（实验性）**：遇到简谱页可改用本机简谱模块 `jianpu.py`（数字模板匹配 + 版面解析，直接输出内部音符模型，不依赖 Audiveris/homr）。在「识别设置」里选好调号（1 = ?）与拍号后点「按简谱识别这一页」；**多页简谱要点「按简谱识别全部 N 页」**（见下文）。它能读数字音级、上下八度点、减时线层数、附点、延长号「-」、休止「0」与多声部行，并回传每个音符在页面上的真实像素坐标（因此在谱面上画点、点选定位对简谱可用）。整本简谱同样走批量接口：一次启动解释器、数字模板只渲染一次，实测 **0.09–0.17 秒/页**（逐页调用约 0.42–0.50 秒/页）。
- **识谱自检（拍数核对）**：识别完成后会逐小节核对「本小节所有音符+休止的拍数是否等于拍号」，把对不上的小节**点名列出**（例如「⚠ 自检：第 9、12、18 小节拍数对不上」），提示优先核对这些位置。这是准确率的兜底——漏音、多看一条减时线、延长号误判都会表现为某小节拍数异常。乐理上合法的「不完整小节」不会误报：**弱起小节、最后一小节不满、只含休止的整小节**都会放过（规则与测试见 `tests/jianpu-corpus.test.mjs`）。
- **6 种合成音色 + 67 种真实采样音色，每个声部都能单独选**：「全局音色」下拉按
  **钢琴 / 键盘、弦乐、中国民族乐器、人声（合唱）、管乐、铜管、萨克斯、弹拨 / 吉他、贝斯、合成** 十组显示，合计 **73 种音色**（采样 67 + 合成 6）。
  合成音色（开箱可用）：钢琴、弦乐、混声合唱、**女声合唱（合成）**、管风琴、电子琴。
  真实采样音色（需先装音源，见上文；没装时自动退回同类合成音色）：
  - 钢琴 / 键盘：真实钢琴、电钢琴、羽管键琴、颤音琴、教堂管风琴、温暖铺底；
  - 弦乐细分：真实弦乐合奏、小提琴、中提琴、大提琴、低音提琴、拨弦、震音弦乐、竖琴；
  - 人声（合唱）：**真实女声合唱、真实男声合唱、真实混声合唱**（Sonatina 的男女声样本是分开采的：
    女声 G4–C6、男声 G2–F#4，混声按音域取用）、人声「哦」、合成人声合唱；
  - 管乐：长笛、单簧管、双簧管、大管、小号、圆号、长号。
  **声部面板每一行还有自己的音色下拉**（默认「跟随全局」），可以做成「女高=真实女声合唱、女低=真实女声合唱、男高/男低=真实男声合唱、钢伴=真实钢琴」这种组合。设置会记在本地，下次打开同一份乐谱还是这套配置。
  每行还有一个「原八度 / 低八度 / 高八度」下拉：识别引擎偶尔漏读男高音谱号下面的小「8」（8vb），整个声部会高八度，用它就能只把那个声部校回来。
  - 钢琴（合成）：两条微失谐（1.9 音分）的「弦」叠加（真实钢琴同音 2–3 根弦的拍音）+ 泛音加法 + 低通「亮度包络」（起音亮、余音暖）+ 击弦噪声 + 高音快制音的两段衰减；
  - 弦乐（合成）：三条微失谐锯齿波 + 低通 + 慢起弓；
  - 合唱人声（合成）：两条微失谐声带波 + 三段元音共振峰（「啊/哦/诶/呜」按声部分配）+ 5.1 Hz 颤音 + 气口噪声 + 慢起音；
    **合成女声**用更高的女声共振峰（F1/F2 高 20%–40%）+ 2.6 kHz 以上补 3.5 dB 高频，与混声/男声区分；
  - 管风琴（合成）：基音 + 八度 + 十二度音栓、慢起音长释放；电子琴（合成）：柔和三角波（最省资源，适合只听音高）。
  采样音色是真实录音回放：FluidR3 每个音一个采样（24 kHz 单声道、3.13 秒、循环撑长音）；
  SSO 合唱每个半音一个采样（约 8 秒、用 SFZ 的精确循环点）；钢琴 2 个力度层、每 3 个半音一个采样点。
  另外：**声部按左右铺开做立体声定位**（钢琴居中），合唱听起来是「一群人」而不是「一个合成器叠几层」；
  所有音色做了响度配平（切换不会忽大忽小）；所有声部共用一条「干声 + 程序生成混响 + 压限 + tanh 软限幅」主链，密集织体也不削波。
  播放调度是**滚动窗口**：只提前 2 秒建音频节点、每 200 毫秒补一次（不是一开始把整曲上千个节点全建出来）——这是「一卡一卡 + 噼里啪啦」的根治办法，见「当前限制」里的性能说明。
  音色参数在 `timbre.js` 里，可脱离浏览器做单元测试（`tests/timbre.test.mjs`）；真实发声由 `tests/e2e-audio.mjs` 用 `OfflineAudioContext` 渲染后做频谱验证（泛音递减、共振峰、混响余音、响度配平、合成女声频谱、逐声部音色、真实采样音域/音高/循环）。
- **识别来源徽标**：明确区分「本机专业识别引擎」「专业引擎 + 部分粗略估算」「粗略估算」「本机简谱识别（实验性）」「来自文件的结构化乐谱」五种结果。
- **逐音置信度**：粗略估算得到的音符会带上置信分，偏低的音符在列表中以色条标出，可一键「只看待校对」。
- **谱面导航**：识别后在谱面上框出每行谱表的识别区域；点音符行会高亮所属谱表，并在该谱表上画出一条虚线标出这个音的音高位置。简谱识别会回传音符的真实像素坐标，这类结果直接在谱面上画音符圆点，点谱面即可定位到对应音符行。
- **挑声部演奏 + 单独调音量**：识别出多个声部时，「03 / 演奏」面板会**每个声部列一行**（按 part 归并：钢琴大谱表也只算一行），勾选决定演奏/导出哪几个声部（默认全选，可「全选 / 全不选」）。每行右边有一根**音量滑条**：觉得钢伴太吵就把它拖小，**播放中拖也立刻生效、不会中断播放**。名字像 Piano/钢琴 的声部还能用「包含钢琴伴奏」开关一键去掉。声部名可在下拉里一键改成谱面上的叫法（女高 / 女中 / 男中 / SOPRANO…）。播放按钮在没有选区时就是**播放全曲**，选了选区则只播那一段。
- **多页简谱整本识别**：简谱是逐页识别的，单页「按简谱识别这一页」只会替换当前结果。多页简谱 PDF 请点**「按简谱识别全部 N 页」**——它会把各页图片**一次**送批量接口识别（省掉每页一次的 Python 启动），再跨页拼成一份连续乐谱（小节号连续、各声部起拍递增），一次就能整曲播放；批量接口不可用时自动退回逐页流程。五线谱 PDF 对应的按钮是「识别全部 N 页」。
- **翻页不会丢结果**：翻 PDF 页只切换谱面显示，识别结果、校对过的音符、声部勾选与选区都保留，**正在进行的播放也不会被打断**（可以边放边翻页跟着看谱）；谱面坐标点只在「识别时的那一页」上绘制，翻到别的页会收起并提示「识别结果来自第 N 页，仍可播放/导出」。
- **演奏任意一段**：点音符序号（或行内空白处）设选区起点、`Shift`+点设终点，即可只试听/导出这一段，并支持循环播放；片段会自动平移到从第 0 拍开始。
- **演奏反映速度与力度**：读取 MusicXML 的中途速度标记与力度记号（如 Audiveris 输出的 `<sound tempo>` / `<sound dynamics>`），试听时按拍变速、并按力度记号改变音量峰值。
- **自动识别谱面速度（BPM），含中途变速**：识别时如果引擎读到「♩=66」这类标记，会自动填进「速度 BPM」。**不只看第 0 拍**：像《在山魔王的宫殿》这种只在第二页印一次 ♩=138 的谱，会从全曲速度标记里推断起始速度（实测把错用的默认 84 修正为 138）；读不到任何标记时不再假装知道，而是提示按谱面手填。**中途变速会自动分段播放**：谱面有几处速度变化就按几段变速，界面会写「读到 N 处速度变化（♩=A → ♩=B）」；手动改 BPM 时按整曲等比缩放，变速比例保留；导出的 MIDI 也写成分段速度事件。
- **加厚声部（多种乐器一起演奏同一段）**：声部面板有「加厚音色」工具条——
  「＋ 复制成新声部」把当前声部整条复制成新音轨，「＋ 高八度叠加 / ＋ 低八度叠加」复制并整体移调。
  复制出来的是**真实音轨**，所以能单独勾选、单独调音量、单独选 67 种音色之一（例如原曲钢琴 + 新声部弦乐/合唱），
  播放、MIDI 与 MusicXML 导出全部自动包含它。钢琴独奏曲想加弦乐垫底、或让合唱一起唱主旋律，用它两次点击即可。
- **多声部播放性能**：8419 音 / 1141 小节的多声部谱实测播放 p50 6.1ms、p95 12ms；
  首次播放最差一帧从 2142ms 降到 83.5ms（混响脉冲改空闲预热 + 高亮改增量更新 + 每轮只建一个定时器）。
- **识别结果的节奏量化**：本机引擎识别出的时值常带零头（0.375 拍、3.75 拍…），播放会「散」。保存前会按拍号把小节内的起拍吸附到 1/4 或 1/2 拍网格、时值取整、同音重复去重——只改节奏、不改音高，MusicXML 导入的结果不受影响。
- **整体移调**：±12 半音一键校正系统性音高偏差，已手动校对过的音符不会被覆盖。
- **标题可直接编辑**：识别引擎常把谱面编号当成标题，点击标题即可改掉。
- 可点谱面标记定位音符，校对音高、起拍和时值，增删音符；可选择声部/谱表单独试听与导出 MIDI。
- homr 未安装时，五线谱图片可用本地规则逐行估算；可选择高音、低音、中音或次中音谱号。
- 可选调用本机 [homr](https://github.com/liebharc/homr) 识谱；把 `homr` 命令放入 PATH，或在启动前设置 `HOMR_EXECUTABLE` 为可执行文件完整路径。homr 输出会在临时目录处理后删除。本机识谱代码/模型不随本项目捆绑，homr 使用 AGPL-3.0，需按上游说明单独安装并遵守其许可证。

## 当前限制

- **识别精度基准的范围**：简谱侧已有《敕勒歌》第 11 页的**人工逐小节核对**基准
  （`tests/fixtures/chilele_p11_jianpu.ground-truth.json`，119 音符 / 12 小节 / 4 声部），
  并在 **3× 与长边 2600px 两种渲染尺寸**下都锁到 100%（见 `tests/jianpu-pages.test.mjs`）；
  另有《从前慢》4 页 + 参考页的**回归语料**（`tests/fixtures/jianpu_corpus.json`），
  固定住音符数/声部/小节/自检结论，防止「修一个坏一个」。但它们仍是**本项目的回归基准，
  不是第三方独立标注**。五线谱页（p1–p10）的人工基准尚未建立。
- **「任意简谱 100% 正确」目前做不到，也不打算假称做到**：识别错误来自图像本身（模糊、扫描歪斜、
  手写谱、装饰字体、印刷毛刺）与符号歧义（连音弧和减时线在像素上几乎一样），这是识别任务的
  客观上限，任何 OMR 都无法保证。本项目的做法是让**有效准确率**尽量逼近 100%：
  ① 参考语料上的识别锁到 100% 并持续回归；② 逐小节拍数自检，把可疑小节点名，不让错误静默通过；
  ③ 音符可逐条校对（音高/起拍/时值/增删），改完立刻能听；④ 播放前可选「只看待校对」标出低置信度音符。
  换句话说：**识别不保证 100%，但「错误一定看得见、改起来很快」是有保证的。**
- **五线谱引擎只识别五线谱**：Audiveris 与 homr 都不支持简谱（数字谱）。遇到**简谱**页面，应用会提示改用本机简谱模块，而不是给出一堆错误音符。
- **简谱识别仍属实验性，限制如实列出**：只按「计算机排版、印刷清晰」的简谱设计，扫描件、手写谱、字体差异大的谱不保证；**到目前只在两份真实合唱简谱（《敕勒歌》《从前慢》）上验证过**，换字体或换版式都需要重新核对——实测《从前慢》就暴露出「英文声部标签的字母 O 被读成数字 0」「引子括号被读成 0」两个凭空造音的缺陷，以及「歌词行被当成声部行、把一屏 4 条声部行桥接成一大块，读出 5 个声部/重复音符」的缺陷（均已修，见 [下一步优化方向.md](下一步优化方向.md)），也仍有小节拍数偶发不符的情况；**调号与拍号需要手动选择**，页眉的「1 = ?」尚未自动读取；多声部靠「系统内按纵向位置分块 + 分叉小节判定」推断声部归属，非常规排版会误判；个别印刷毛刺或漏检的小节线会让某小节的拍数与拍号不符（此时会给出「第 N 小节内容为 X 拍」的警告 + 连音弧/延音线排查提示，请重点校对那几小节）；歌词不识别；声部名称统一显示为「声部1…N」。引擎可用 `jianpu.py --summary`（紧凑结果）与 `jianpu.py --dump`（版面结构）单独排查。
- **连音弧与减时线在像素上不可分**：两者形状几乎一样（实测连音弧的平段正好落在下一个数字字底下方 2px 处）。
  所以引擎**不会**自动根据弧线改时值——只在某小节超出拍号时如实报告位置并要求人工核对。
  同理，「同音高 + 首尾相接」只作为**延音线候选**报告，不自动合并（分不清是延音线还是同音反复）。
- **图片型（扫描/截图）PDF 的分辨率决定识别上限**：有些 PDF 每页只是一张位图——例如用户给的《有我》每页是 1279×1707 的 JPEG（约 **155 DPI**，8 页）。缩编合唱谱在这么小的字上，符头/符干只有几个像素，任何 OMR 都会读错节奏和音高，调引擎参数也救不回来。本工具会检测出来并直接提示「这份 PDF 是图片型文档，约 155 DPI，建议换 300 DPI 以上清晰扫描件或矢量 PDF」；识别这类文件请务必逐音校对。
- Audiveris 需要较高分辨率才能可靠检测谱线（实测约 scale ≥ 3.0）；普通 PDF 的识谱图按 2600px 长边渲染（PNG 无损），低清图片型 PDF 会放大到 5.0× 并做轻度锐化再送识别。即使这样，155 DPI 的缩编谱仍会有逐音错误（实测「4 拍小节」约 86–96% 的页、也有 42% 的页），**识别结果务必逐音校对**；换 300 DPI 以上扫描件或矢量 PDF 是提高准确率最有效的办法。
- **8vb 谱号可能漏读**：男高音常用「高音谱号下面加一个小 8」（实际低八度）。分辨率不够时引擎会把它当普通高音谱号，男高声部整体高八度；可用声部面板的八度下拉一键校回，再对照「整体移调」核对。
- Audiveris 对个别音符仍可能漏读（实测《敕勒歌》第 1 页钢琴声部漏读一个 E4），结果**必须逐音校对**。
- 未安装引擎时，图片/PDF 扫描页只用像素规则粗略估算音高及时值，不会可靠识别调号、休止符、附点、连音、歌词、奏法或复杂复调。
- 引擎可识别的范围和精度由其模型与输入质量决定；力度、奏法、重升降号等不完整，不能保证任意符号。
- 五线谱引擎输出的音符**不含谱面坐标**，因此不会在谱面上画音符圆点。界面改为框出每行谱表的识别区域，并在点选音符时画出该音高对应的基准虚线（纵坐标由音高精确推算，横坐标不做猜测）。简谱识别是例外：它回传真实坐标，会直接画点。
- 整页识别（Audiveris）单页约 9–20 秒；整本一次批量识别约 **4–9 秒/页**（页数多时自动多进程并行），
  16 页混合谱（前 10 页五线谱 + 后 6 页简谱）实测约 **41 秒**。普通 PDF 的识谱图仍按 2600px 长边渲染
  （只是改成 PNG 无损、不再二次压缩），耗时与以前接近；**图片型低清 PDF 会放大到 5.0× 并锐化，更准但更慢**
  （实测 8 页约 65–78 秒、单页约 15–25 秒；装了 OCR 语言包后 Audiveris 会多跑一步文字识别）。
  逐行识别（homr）单行约 7 秒、一页 12 行约 90 秒（本机 CPU 推理）。简谱整本约 0.1–0.2 秒/页。
  识别速度取决于本机 CPU 与页面分辨率。
- 播放性能：滚动调度后，整曲 1400+ 音符时音频图里同时只有几十个音频节点（实测 48 个），
  点击播放不再有约 0.8 秒的卡顿；若机器特别老、CPU 占用高，仍可能出现轻微断续——可把音色换成「电子琴」（最省资源）。
- 整行休止（或该声部尚未进入）的谱表会被识别为「没有音符」，这是正常结果，界面会单独统计。
- MusicXML 导入用于演奏结构化音符，并不自动识别原始图片；目前只支持 partwise，不支持 timewise 排列。
- 当前试听有 **73 种音色**（6 种合成 + 67 种真实采样，见「当前支持」与 [乐器音源清单](docs-instruments.md)）：合成音色开箱可用；
  真实采样音色要先装音源（全装约 70 MB，可只装某一类）。采样音色是录音回放，比合成音色真实，
  但人声只有「啊/哦」的元音铺底、**不会唱词**；女声/男声/混声是**三套不同的样本**（不是把混声升调），
  但都只是「啊」的合唱，不是真人唱词。钢琴 3 个半音一个采样点、2 个力度层；其他采样乐器 88 个音、1 层力度。
  已支持中途速度变化与力度记号；装饰音、歌词、反复跳转与奏法/颤音仍不会体现在演奏中，界面会提示相应限制。
  合成音色能表达音高、时值、力度与起奏方式，但**不能替代真人演唱/真钢琴音色库**；若需要更真实的声音，可导出 MIDI 用音源加载。
- MusicXML 的微分音可在浏览器合成试听中播放；标准 MIDI 使用整数半音，导出时会四舍五入到最近半音。
- 本项目不捆绑 OMR 引擎；`.tools/` 与 `.venv/` 均已在 `.gitignore` 中排除，需按上述步骤自行安装。

## 乐理约定（识别与播放遵守的规则）

本项目不是「猜个大概」，下面每条规则都来自乐理、并写成了代码与测试（`tests/music-theory.test.mjs`）：

| 记号 / 概念 | 乐理含义 | 本项目怎么处理 |
|---|---|---|
| **调号 `1 = X`** | 简谱是**首调唱名**：数字 1 唱 do，`1=F` 表示 do 的实际音高是 F。数字 n 的音高 = do + 大调音阶第 n 级半音数 | 界面选 `1 = ?`；`1=C→60`、`1=F→65`、`1=G→67`、`1=A→69` 等，已覆盖 12 个调 |
| **八度点** | 点在数字**下方** = 低八度（−12 半音），点在**上方** = 高八度（+12） | 按「点在字框上/下的方位」判定，判据用**字高比例**而非固定像素 |
| **减时线（下划线）** | 一条下划线 = 时值减半（八分音符），两条 = 十六分音符 | n 层 = `1/2^n` 拍 |
| **增时线 / 延长号 `-`** | 数字右边一根横线 = 延长一拍，`-` 可叠加 | 每根 `+1` 拍，且只算落在本小节范围内的 |
| **附点** | 附点 = 原时值的 1.5 倍 | `×1.5` |
| **休止 `0`** | 不发声，但**占时值** | 计入小节拍数与时间轴，不进播放列表 |
| **延音线（tie）/ 圆滑线（slur）** | 延音线连接**相同音高**，时值相加、只发音一次；圆滑线连接**不同音高**，只要求连贯、**不改变时值**（[Flat 的解释](https://blog.flat.io/zh/yuanhuaxian-de-zuoyong/)） | 「同音高 + 首尾相接」只作为**延音线候选如实报告位置**，**不自动合并**（像素上分不清它是延音线还是同音反复）；圆滑线不影响时值，所以不处理 |
| **弱起小节（anacrusis）** | 乐曲开头常是不完整小节，其后紧跟完整小节 | 若「第 1 小节 + 末小节 ≈ 一个完整小节」则按弱起处理，避免整曲起拍后移 |
| **三连音** | 三个音占两个音的时值（×2/3） | 代码已实现但**默认关闭**（`TRIPLETS_ENABLED=False`）：记号字号偏小认不出，打开只会误判，见「下一步优化方向.md」 |
| **拍号** | 4/4、3/4、2/4、6/8、9/8、12/8 等，决定每小节拍数 | 界面可选；6/8 = 3 拍、9/8 = 4.5 拍、12/8 = 6 拍（按四分音符为 1 拍折算） |
| **每小节拍数自检** | 除弱起小节与末小节外，每小节的音符+休止总时值都应等于拍号 | 逐小节核对，把不符的小节点名（`selfCheck`），并提示校对；弱起/末小节/只含休止的短小节不误报 |
| **力度 / 速度** | `mf`/`p` 改变音量，`<sound tempo>` 改变速度 | MusicXML 里的力度/速度会接进播放（见「当前支持」） |

**诚实边界**：以上规则只保证「按规则算得对」；**谱面本身读错**（漏音/错音/连音弧误判）
仍会出现，界面会如实报警告并要求人工校对——这是产品定位，不是缺陷。

```bash

node tests/benchmark.mjs tests/fixtures/chilele_p11_jianpu.ground-truth.json result.json
```

`tests/fixtures/chilele_p11_jianpu.ground-truth.json` 是《敕勒歌》第 11 页（简谱）的回归基准：
由 `jianpu.py` 识别后经**人工逐小节核对**（12 小节、4 声部与谱面吻合），
但**它是本项目的回归基准，不是第三方独立标注**——文件里的 `provenance` 字段写明了这一点，
已知歧义小节（第 10、12 小节为 4.75 / 4.5 拍）也如实保留在 `warnings` 里，没有被抹平。
因此「基准 vs 当前引擎输出」得到满分只说明**没有回归**，不等于绝对精度。
p1–p10（五线谱页）的人工基准尚未建立——那需要逐页标注音符，本轮未做，如实记在
[下一步优化方向.md](下一步优化方向.md) 的 P0-2。

## 安全说明

本地服务只服务项目根目录下的白名单静态文件（`.html/.css/.js/.mjs/.json/.md/.svg/.ico/.png`），
以及 `vendor/` 下的本地依赖（如 pdf.js）；拒绝 `.venv`、`node_modules`、`.git`、`tests` 等目录与目录列表，校验 `Host` 头，并附带 CSP 等安全响应头。
`/api/omr/recognize` 只接受 PNG/JPEG、限制 25 MB，且同一时刻只处理一个识谱任务。
`.assets/` 目录只用于存放**使用者本机安装的采样音源**（`.mp3`/`.wav`/`.json`/`.md`；SSO 合唱样本是 WAV），
同样受后缀白名单约束；样本不进 git、也不随仓库分发（许可与署名见 `音源接入方案.md`）。
`/api/omr/recognize-batch` 与 `/api/jianpu/recognize-batch` 是整本识别接口：只接受 JSON + base64 PNG/JPEG，
单次最多 32 页、请求体最多 64 MB，与单页接口共用同一个并发闸门（一次只跑一个识谱任务），并对每张图校验文件头。
`/api/jianpu/recognize`（简谱识别）同样只接受 PNG/JPEG、限制 25 MB、与 OMR 共用同一个并发闸门；
它把页面交给同目录的 `jianpu.py` 处理（需要 `opencv-python`/`Pillow`，随 homr 装在项目 `.venv`；
也可用 `JIANPU_PYTHON` 指向别的解释器）。缺少依赖时接口返回 503 并说明原因，界面据此提示，而不是报错崩溃。
识谱子进程的 `TMP/TEMP` 会被指到本次请求自己的临时目录：Audiveris（JVM）默认写系统 `%TEMP%`，
在部分受限电脑上不可写，会导致整页识别在 PAGE 步骤失败——这是实测踩过的坑，已固化在 `serve.py` 的 `omr_child_env()`。

真实音源的调研（GitHub 上可用的免费钢琴/乐器/人声、许可与体积、五种技术路线对比，
以及「女声/男声合唱为什么分开」「弦乐怎么细分」的说明）见 [音源接入方案.md](音源接入方案.md)。

你提供的完整符号清单与逐项支持状态见 [符号支持清单.md](符号支持清单.md)。公开项目比较见 [GitHub参考项目调研.md](GitHub参考项目调研.md)。
